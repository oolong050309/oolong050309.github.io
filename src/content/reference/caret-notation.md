## 为什么是异或 64

回车只有一个字符，ASCII 编号是 13。它通常没有可见的形状，所以有些终端工具把它显示成 `^M`。脱字符 `^` 提醒读者这里有一个控制字符，后面的 `M` 用来区分是哪一个。

对 ASCII 控制字符（编号 0～31 和 127），显示规则可以写成 **控制字符编号 XOR 64**。结果是要显示的 ASCII 字符编号，再在该字符前加上 `^`。

把 64 写成二进制是 `01000000`，只有权值为 64 的那一位是 1。和它异或时，这一位会从 0 变成 1，或从 1 变成 0，其余各位保持原样。

```text
CR    00001101  (13)
XOR   01000000  (64)
    = 01001101  (77, M)  → ^M

DEL   01111111  (127)
XOR   01000000  (64)
    = 00111111  (63, ?)  → ^?
```

对于 0～31，权值 64 的位原本是 0，翻转后就相当于加 64，正好映射到从 `@` 到 `_` 的可见字符。DEL 的这一位原本是 1，翻转就相当于减 64，于是 127 变成问号 `?` 的编号 63。`^M` 和 `^?` 用的是同一个映射。

## 从显示反推原字符

同一位翻转两次就会回到原来的值。反查时，对脱字符后面的符号再异或一次 64 即可。比如，`^J` 里的 `J` 是 74，`74 XOR 64 = 10`，对应换行（LF）。`^?` 也一样，`63 XOR 64 = 127`，对应 DEL。

| 原字符 | ASCII 编号 | 异或 64 后的编号与字符 | 显示 |
| --- | ---: | --- | --- |
| NUL，空字符 | 0 | 64 → `@` | `^@` |
| ETX，正文结束 | 3 | 67 → `C` | `^C` |
| HT，水平制表 | 9 | 73 → `I` | `^I` |
| LF，换行 | 10 | 74 → `J` | `^J` |
| CR，回车 | 13 | 77 → `M` | `^M` |
| ESC，转义控制字符 | 27 | 91 → `[` | `^[` |
| DEL，删除字符 | 127 | 63 → `?` | `^?` |

## Ctrl 键怎样生成控制字符

按键输入和显示记号分别由终端处理。以早期的 DEC VT100 为例，按下 Ctrl 时，终端固件会查表确认这个组合键能生成控制字符，再把字符编号中权值为 32 和 64 的两位清零，保留低五位。`M` 是 77，`m` 是 109，两者的低五位都是 `01101`，因此 Ctrl+M 会发送编号 13 的回车。Ctrl+I 也会按同样的规则发送编号 9 的水平制表符。

现代终端通常保留这类映射，所以在收到相同控制字符的程序看来，Ctrl+M 和回车、Ctrl+I 和 Tab 的效果可以相同。具体按键行为由终端和应用决定。显示端则只需知道原来的控制字符编号。例如，工具处理编号 13 时，即使它来自文件，也可以显示为 `^M`。

## 在终端里观察

在 macOS 或 Linux 上，`printf` 可以写出字母 `A`、回车和换行，再交给 `cat -v` 显示。

```sh
printf 'A\r\n' | cat -v
# A^M
```

屏幕先显示 `A^M`，然后换行。这里 `cat -v` 把回车显示成 `^M`，保留换行原有的显示；输入里的回车仍然是编号 13。用这种工具查看 CRLF 行尾的文件，往往能在每行末尾看见 `^M`。

不同工具可以用不同的代码实现这张映射表。例如 GNU `cat` 对 0～31 中需要显示的字符用加法，对 127 直接输出 `^?`。结果与异或公式一致。

看到 `^C` 时，先看它出现在什么地方。文件查看器可能用它表示编号 3 的控制字符；交互式终端也可能在按下 Ctrl+C 后回显它。常见终端设置会把这个输入用作中断，向前台进程发送信号。

普通文本里的 `^M` 由两个字符组成。它能否代表一个回车，要看工具是否明确使用了脱字符表示法。写程序时，诸如 `"\r"` 的字符串转义则由语言解释，结果可以直接包含一个回车字符。
