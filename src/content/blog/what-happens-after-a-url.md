你输入一个网址，按下回车，网页就出现了。这个平常到不能再平常的动作，背后其实有一群小伙伴在接力。

我们先看最常见的 HTTPS 访问过程。浏览器缓存、代理、连接复用等机制可能省去其中的一些步骤，但这张地图能帮助我们找到方向。

## 第一步 找到地址

网址里的域名方便人记忆，网络通信还需要知道目标的 IP 地址。浏览器和操作系统会先检查已有的缓存，必要时再向 DNS 解析服务查询。

可以把 DNS 想象成通讯录：你知道朋友的名字，还要找到对应的联系方式。不过，同一个域名可能对应多个地址，通讯录也会定期更新。

## 第二步 建立连接

对于使用 HTTP/1.1 或 HTTP/2 的 HTTPS 请求，通常需要先建立 TCP 连接，再进行 TLS 握手。TLS 帮助确认通信对象并协商加密方式。

HTTP/3 则使用基于 UDP 的 QUIC，把可靠传输和 TLS 握手结合在一起。因此，“所有网页请求都先建立 TCP 连接”并不准确。

## 第三步 发送一封小信

连接准备好后，浏览器发送 HTTP 请求。概念上，它在问：“请把这个页面给我。”

```http
GET / HTTP/1.1
Host: example.com
Accept: text/html
```

服务器返回状态码、响应头和内容。HTML 中还可能引用 CSS、图片和脚本，它们会触发后续请求。

## 第四步 把内容变成页面

浏览器解析 HTML，处理样式，计算布局，再把像素绘制到屏幕上。脚本可能继续修改页面，因此“下载结束”和“页面完成”也不是同一个时刻。

> 下一次网页加载缓慢时，可以先问：是地址查找慢、连接慢、服务器处理慢，还是下载与绘制慢？

把大问题拆成几个小环节，网络就没有那么神秘了。
