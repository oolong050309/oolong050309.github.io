Git 的命令很多，但不必同时记住所有命令。先理解它记录了什么，再看命令怎样改变这些记录。

## 一次提交是一份快照

概念上，Git 的提交记录项目在某个时刻的文件状态。提交还包含作者、说明和父提交等信息。

它不意味着每次都机械地复制整个项目。底层会复用相同内容，并使用压缩等存储手段。

```sh
git add notes.md
git commit -m "写下第一篇笔记"
```

暂存区决定本次提交准备记录哪些内容。工作目录里其他尚未暂存的改动，不会因为执行了这次提交就自动一起进入快照。

## 分支是一个会移动的名字

分支可以理解成指向某次提交的名字。在当前分支上创建新提交后，这个名字通常会向前移动。

```sh
git switch -c try-an-idea
```

创建分支并不需要复制一整个项目目录。我们只是给一条探索路线起了个名字。

## 回头看比背命令更有用

在一个练习仓库里创建几次提交，再查看历史：

```sh
git log --oneline --graph --all
```

把每次提交画成节点，把父提交关系画成线，分支、合并和历史就从术语变成了一张能读懂的地图。
