ASCII 的全称是 American Standard Code for Information Interchange，通常译为「美国信息交换标准代码」。它为一组字符与控制功能安排了编号，便于不同设备交换文本。

例如，ASCII 规定字母 `A` 的编号是 65，小写字母 `a` 的编号是 97，空格的编号是 32。发送方按照这套约定把字符表示为数字，接收方再按照同一张表还原字符。

```text
字符 "A" → ASCII 编号 65 → 字符 "A"
```

**字符与数字之间的对应关系，需要由一套共同的规则确定。** ASCII 提供的就是这样一张字符表。

## ASCII 怎样给字符编号

标准 ASCII 共有 128 个编码位置，编号为 0～127，包含英文字母、数字、标点、空格和控制字符。

按编号看，可以把字符表分成下面几段。

| ASCII 编号 | 内容 | 示例 |
| --- | --- | --- |
| 0～31 | 控制字符 | NUL 是 0，LF 是 10 |
| 32 | 空格 | 缩写是 SP |
| 33～47 | 标点和符号 | `!` 是 33，`/` 是 47 |
| 48～57 | 数字字符 | `0` 是 48，`9` 是 57 |
| 58～64 | 标点和符号 | `:` 是 58，`@` 是 64 |
| 65～90 | 大写字母 | `A` 是 65，`Z` 是 90 |
| 91～96 | 标点和符号 | `\` 是 92，`^` 是 94，`_` 是 95 |
| 97～122 | 小写字母 | `a` 是 97，`z` 是 122 |
| 123～126 | 标点和符号 | `{` 是 123，`~` 是 126 |
| 127 | 删除控制字符 | 缩写是 DEL |

ASCII 中的字母和数字各自连续排列。比如，知道 `A` 是 65，就能推算出 `B` 是 66。标点和符号分布在这些连续区间之间。全角逗号 `，` 和直角引号 `「」` 则超出了 ASCII 的范围。

例如，大写 A 与小写 a 的编号相差 32。但这种关系只适用于这些具体的 ASCII 字母，不能直接推广为所有语言的大小写转换规则。

## 数字 5 与字符「5」

整数 5 表示一个数值；字符串 `"5"` 包含一个数字字符。ASCII 为字符 5 分配的编号是 53：

```text
字符 "5" → ASCII 编号 53
```

类似地，文本 `"65"` 包含两个字符，对应两个 ASCII 编号：

```text
"6" → 54
"5" → 53

"65" → [54, 53]
```

而字符 `A` 只对应编号 65。虽然它的编号是 65，字符 `A` 与文本 `"65"` 仍然是不同的内容。

这也解释了为什么从文本读取数字时需要转换：程序需要把数字字符组成的字符串，解析为能够参与运算的数值。

## 空格和控制字符也是数据

32～126 通常被归入可打印字符。其中空格（SP，32）占据一个位置，显示时留白。0～31 和 127 是控制字符，许多最初用于操纵打印设备、分隔数据或协调通信。一个控制字符在今天的具体作用，取决于读取它的程序或协议。

### 常见控制字符

| ASCII 编号 | 缩写 | 含义 |
| ---: | --- | --- |
| 0 | NUL | 空字符。C 风格字符串用它标记结束，Python 字符串则可以把它作为普通的一个字符保留 |
| 7 | BEL | 响铃。终端收到它时，可能发出提示音、闪屏或保持安静 |
| 8 | BS | 退格。原本让打印位置向左退一格 |
| 9 | HT | 水平制表。移动到下一个制表位置，显示宽度取决于当前位置及设置 |
| 10 | LF | 换行（Line Feed）。原意是向下移动一行 |
| 11 | VT | 垂直制表。移动到下一个垂直制表位置 |
| 12 | FF | 换页。让打印位置移到下一页 |
| 13 | CR | 回车（Carriage Return）。原意是回到当前行的开头 |
| 27 | ESC | 转义控制字符。在终端协议中常作为控制序列的开头 |
| 127 | DEL | 删除字符。早期可用它标记纸带上作废的位置 |

其余控制字符也有各自的历史用途。比如，SOH、STX、ETX 和 EOT 用来标记报头、正文或传输的边界。ENQ、ACK 和 NAK 用于询问、确认或拒绝确认。FS、GS、RS 和 US 分别是文件、组、记录和单元分隔符。现代软件也有自己的消息格式，这些字符的解释要以实际协议为准。

CR 和 LF 原本分别负责横向和纵向移动。现代文本文件中，Unix 系统通常用单个 LF 分行，Windows 文件常见 CR 后接 LF。编辑器都可以把它们显示成一次换行，但两个序列包含的字符数量不同。

## 怎样写出看不见的字符

回车的编号是 13。文档可能把它写作 `CR` 或 `<CR>`，终端诊断工具可能显示 `^M`，界面上也可以用 `␍` 标出它。在 Python 里，可以写 `"\r"` 来构造一个回车。前几种便于人读，最后一种是程序构造字符串的语法。

### 缩写和可见符号

`NUL`、`LF`、`ESC` 等是名字的缩写。规范、编辑器或调试输出也可能把它们写成 `<LF>` 或 `[ESC]`。方括号和尖括号通常是文档或工具加上的标记，具体样式可以不同。

Unicode 还提供了专门用于显示这些字符的符号，比如 `␀` 表示 NUL，`␉` 表示 HT，`␊` 表示 LF，`␍` 表示 CR，`␛` 表示 ESC。它们有自己的字符编号，适合在界面上标记原文中看不见的字符。空格也可以用 `␠` 或 `␣` 显示。我们的[分词动画](/blog/cs336-tokenization/)用的是 `␣`，输入文本里仍是编号 32 的普通空格。

### 脱字符表示

`^` 叫脱字符（caret）。在脱字符表示法（caret notation）中，`^` 和后面的一个符号一起代表一个控制字符。比如 `^I` 对应水平制表（HT），`^J` 对应换行（LF），`^M` 对应回车（CR）。

编号 0～31 可以统一计算：给控制字符的编号加 64，再查表找出要写在 `^` 后面的符号。回车的编号是 13，加 64 得到 77，也就是字母 `M` 的编号，所以回车写成 `^M`。DEL 的 `^?` 是单独约定的写法。

| 脱字符表示 | ASCII 编号 | 对应字符 |
| --- | ---: | --- |
| `^@` | 0 | NUL |
| `^C` | 3 | ETX，正文结束 |
| `^D` | 4 | EOT，传输结束 |
| `^H` | 8 | BS，退格 |
| `^I` | 9 | HT，水平制表 |
| `^J` | 10 | LF，换行 |
| `^M` | 13 | CR，回车 |
| `^[` | 27 | ESC |
| `^_` | 31 | US，单元分隔符 |
| `^?` | 127 | DEL |

在 macOS 或 Linux 上，可以用下面的命令观察这种显示。`printf` 输出字母 `A`、一个回车和一个换行。`cat -v` 把回车显示为 `^M`，最后的换行仍然显示为换行。

```sh
printf 'A\r\n' | cat -v
# 输出 A^M，然后换行
```

在普通 Python 字符串中直接写 `"^M"` 会得到 `^` 和 `M` 两个字符。在终端按下 Ctrl+C 时看到的 `^C`，则可能是终端对输入的回显。在常见的终端设置下，Ctrl+C 会向前台进程组发送中断信号。类似地，在终端的默认行输入模式下，在空行按 Ctrl+D 通常会让读取操作得到文件结束的结果。这是终端对按键的处理，与文件里保存编号 4 的 EOT 字符是两回事。

### Python 的反斜杠转义

在 Python 的普通字符串里，反斜杠 `\`（编号 92）可以引出一段转义序列。正斜杠 `/`（编号 47）可以直接写在字符串里，比如 `"notes/ascii"`。

| 写法 | 字符 | ASCII 编号 |
| --- | --- | ---: |
| `\0` | NUL | 0 |
| `\a` | BEL，响铃 | 7 |
| `\b` | BS，退格 | 8 |
| `\t` | HT，水平制表 | 9 |
| `\n` | LF，换行 | 10 |
| `\v` | VT，垂直制表 | 11 |
| `\f` | FF，换页 | 12 |
| `\r` | CR，回车 | 13 |
| `\"` | 双引号 | 34 |
| `\'` | 单引号 | 39 |
| `\\` | 反斜杠 | 92 |

`\"` 和 `\'` 在字符串需要包含与外层相同的引号时特别有用。比如 `"她说：\"你好\""` 得到的文本是 `她说："你好"`。也可以改用单引号包围整个字符串，让里面的双引号直接出现。

下面把几种容易混淆的写法并排比较。`len()` 数的是字符串里的字符，`repr()` 给出便于检查的显示形式。

```python
print(len("\n"), repr("\n"))    # 1 '\n'
print(len("\\n"), repr("\\n"))  # 2 '\\n'
print(len(r"\n"), repr(r"\n"))  # 2 '\\n'
print(len("\r\n"))              # 2
print(len("^M"), len("\r"))     # 2 1
```

`"\n"` 里是一个实际的换行符。`"\\n"` 中前两个反斜杠合起来表示一个反斜杠，再加一个字母 `n`。带 `r` 前缀的是原始字符串，像 `\n` 这样的写法会保留为原文中的两个字符，所以 `r"\n"` 和 `"\\n"` 得到相同结果。原始字符串适合需要保留许多反斜杠的内容，如路径 `r"C:\new\test"`，但结尾的反斜杠数量不能是奇数。

还可以按编号或 Unicode 名称指定字符。下面每种写法都得到字母 `A`。`\x` 后固定跟两位，`\u` 后是四位，`\U` 后是八位，`\N{...}` 使用字符名称。以数字开头的 `\101` 是另一种按编号写字符的形式。

```python
print("\101", "\x41", "\u0041", "\U00000041", "\N{LATIN CAPITAL LETTER A}")
# A A A A A

print(ord("\x1b"), ord("\x7f"))  # 27 127，对应 ESC 和 DEL
```

不同语言和数据格式各自规定转义写法。比如 JSON 允许把正斜杠写成 `\/`，`"/"` 与 `"\/"` 解析后都是一个正斜杠。Python 字符串里直接写 `"/"` 就可以。[Unicode 篇](/blog/unicode/#文件编码声明与转义)还会用 `\u` 对比源代码的写法和字符串实际包含的字符。

## 用 Python 观察 ASCII

Python 的 `ord()` 返回单个字符的 Unicode 码点，`chr()` 完成相反的转换。Unicode 的前 128 个码点与 ASCII 编号保持一致，因此可以先用它们观察 ASCII 范围：

```python
ord("A")       # 65
chr(65)        # 'A'
ord("5")       # 53
int("5")       # 5
```

也可以把一段文本中的每个字符转换成编号，再还原成文本：

```python
text = "Hello, A!"
codes = [ord(char) for char in text]

print(codes)                             # [72, 101, 108, 108, 111, 44, 32, 65, 33]
print("".join(chr(code) for code in codes)) # Hello, A!
```

这里使用的字符都在 ASCII 范围内，因此 `ord()` 得到的值与 ASCII 编号一致。按顺序保存这些编号，就能通过同一套对应关系还原原文。

也可以观察不可见字符：

```python
text = "A B\n"
print([ord(char) for char in text]) # [65, 32, 66, 10]
```

字符串中有字母、空格和换行，每一项都参与编码。程序如果随意去掉空白，就已经改变了原始文本。

## 128 个位置为什么不够

ASCII 可以表示这里使用的英文字母，却不能独立表示汉字、许多带重音的字母和其他文字：

```python
try:
    "猫".encode("ascii")
except UnicodeEncodeError:
    print("ASCII 中没有这个字符")
```

这不是「猫」无法被计算机保存，而是所选编码没有为它提供表示方式。

一种扩展方向是把编号范围扩大到 0～255。但额外增加 128 个位置，仍然无法覆盖世界上的文字；不同系统也可能为新增的编号安排不同字符。因此，「扩展 ASCII」这个名称本身不足以确定唯一的编码表。

面向不同地区与文字的编码陆续出现，包括中文环境中的 GB2312、GBK、GB18030，以及处理繁体中文时会遇到的 Big5 等。它们有各自的历史与规则。交换文本时，如果双方使用不同的解释方式，同一份数据就可能被还原为错误的文字。

继续扩大各自的表，并不能自动解决跨系统交流的问题。我们还需要共同的字符标准，以及能够表示这些字符的编码形式。

## 从 ASCII 走向 Unicode

[Unicode](/blog/unicode/) 为更广泛的文字提供统一的字符与码点体系，同时规定 UTF-8、UTF-16、UTF-32 等编码形式。ASCII 中的字符保留了原来的编号；UTF-8 也兼容这些字符原有的编码表示。

因此，一段完全由 ASCII 范围字符组成的文本，可以使用 UTF-8 正确读取。这为旧文本、协议与软件提供了重要的兼容基础。

理解 ASCII 之后，可以继续在 Unicode 篇中追踪「猫」和 Emoji：它们怎样获得码点，又怎样被编码和保存。回到 [Tokenization](/blog/cs336-tokenization/) 时，也就能分清字符编号和词表编号各自在描述哪一层数据。
